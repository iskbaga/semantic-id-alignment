# Mitigating Collaborative Semantic ID Staleness in Generative Retrieval

This is the official implementation of the paper **"Mitigating Collaborative Semantic ID Staleness in Generative Retrieval"**.

The repository contains the complete source code and experimental assets required to reproduce all results reported in the paper, including:
- Data preprocessing notebooks for 3 benchmarks (Amazon Beauty, Yambda, VK-LSVD)
- Training code for **SASRec**, **RQ‑VAE tokenizers** (TIGER / LETTER-style), and a **TIGER** generative retriever
- A **checkpoint-compatible Semantic ID (SID) refresh** via **token alignment** (Greedy / Hungarian)


### Implemented components

- **SASRec**: sequential recommender used as a baseline and collaborative embeddings model
- **RQ‑VAE tokenizer (TIGER-style)**: standard RQ‑VAE tokenization over item embeddings
- **RQ‑VAE tokenizer (LETTER-style)**: RQ‑VAE tokenization with collaborative filtering loss
- **TIGER retriever**: GPT-style generative retriever that decodes SIDs

### SID update policies (paper terminology)

For a fixed *Base* checkpoint trained on an earlier window:

- **FT-old**: fine-tune on fresh logs with **stale** SIDs (no SID rebuild)
- **FT-new**: rebuild SIDs from fresh logs and fine-tune **without** compatibility handling
- **FT-ours**: rebuild SIDs, then **align new tokens to the old vocabulary** (Greedy/Hungarian), and warm-start
  fine-tune
- **Full**: rebuild SIDs and retrain the retriever from scratch on the expanded window

## Data preparation

Data prep is done via notebooks in `notebooks/`. Each notebook downloads / prepares the dataset and writes standardized
artifacts to `data/<dataset>/`.

### Datasets

| Dataset       | Notebook                               | Output directory |
|---------------|----------------------------------------|------------------|
| Amazon Beauty | `notebooks/AmazonBeautyDownload.ipynb` | `data/beauty/`   |

| VK-LSVD       | `notebooks/VkLsvdDownload.ipynb`       | `data/vk-lsvd/`  |

### Expected outputs

After running the notebook for a dataset, you should see files like:

- `global_item_mapping.json` — remapped item ids
- `all_data_interactions_with_groups.parquet` — interactions with a `part` column (temporal split)
- `items_metadata_remapped.parquet` — item embeddings / metadata aligned to remapped ids

> Note: Some datasets provide embeddings directly (e.g., VK-LSVD/Yambda), while Amazon Beauty uses an embedding pipeline included in the notebook.

## Temporal split and “parts”

All experiments use a **strict chronological split** into **10 contiguous blocks** with (approximately) equal number of interactions.
In code, these are stored as an integer column `part` with **0-based** indexing:

- `part ∈ {0, 1, ..., 9}`

In the paper, blocks are numbered **1..10**. Mapping is:

- paper **block k** <-> code **part (k-1)**

### Interval notation used in configs
Configs represent part ranges as **half-open intervals** `[start, end)`.

Example:

- `dataset.train_parts=[0,8]` means parts `0..7`
- `dataset.val_parts=[8,9]` means part `8`
- `dataset.test_parts=[9,10]` means part `9`

This matches the paper’s rolling-origin setup:

- **Base**: train on blocks 1-8 (parts 0-7), select on block 9 (part 8)
- **FT-***: fine-tune on block 9 (part 8), evaluate on block 10 (part 9)

## Reproducing paper experiments

All training entrypoints live in `scripts/<component>/` and use **Hydra** for configuration.
You can override any parameter from the command line.

### Common conventions

- Replace `<dataset>` with `beauty`, `yambda`, or `vk-lsvd` (depending on what your configs expect).
- Outputs are written under `temp_files/`:
    - `temp_files/checkpoints_<dataset>/` — checkpoints
    - `temp_files/logs_<dataset>/` — TensorBoard logs
    - `temp_files/results_<dataset>/` — exported artifacts (embeddings, SID maps, etc.)

### Main results reproducibility

This is the main comparison in Table 2 of the paper: **FT-old vs FT-new vs FT-ours vs Full**.

> Commands below use the `vk-lsvd` dataset and `hungarian` matching method.

#### 1) Train SASRec embeddings

Used when the pipeline expects sequential-model item embeddings as tokenizer input.

```bash
cd scripts
python sasrec/train.py dataset.name='vk-lsvd' training.save_embeddings=true training.device='cuda'
```

This should export embeddings to `temp_files/results_vk-lsvd/.../sasrec/embeddings.pt`.

#### 2) Train the tokenizer (RQ‑VAE)

Choose one:

- `rqvae-letter` for interaction-informed tokenization (LETTER-style)
- `rqvae-tiger` for content-only tokenization (TIGER-style)

```bash
# LETTER-style tokenizer
python rqvae-letter/train.py dataset.name='vk-lsvd' dataset.train_parts='[0,8]' dataset.val_parts='[8,9]'

# TIGER-style tokenizer
python rqvae-tiger/train.py dataset.name='vk-lsvd' dataset.train_parts='[0,8]' dataset.val_parts='[8,9]'
```

This produces SID mappings under `temp_files/results_<dataset>/.../rqvae-*/`.

#### 3) Train the Base retriever (TIGER)

```bash
python tiger/train.py dataset.name='vk-lsvd'
```

#### 4) Run fine-tuning on the “gap” (block 9 / part 8)

**FT-old (stale SIDs):**

```bash
python tiger/finetune_gap.py dataset.name='vk-lsvd' finetune.matching_method='none' finetune.gap_parts='[8,9]' finetune.test_parts='[9,10]'
```

**FT-new (refresh SIDs, no alignment):**

1) retrain the tokenizer on the expanded window (include the gap)
2) fine-tune retriever using the refreshed SIDs

```bash
# retrain sasrec for embeddings on [0,9)
python sasrec/train.py dataset.name='vk-lsvd' training.save_embeddings=true dataset.train_parts='[0,9]'

# 1) retrain tokenizer on [0,9)
python rqvae-letter/train.py dataset.name='vk-lsvd' dataset.train_parts='[0,9]'

# 2) fine-tune TIGER using refreshed SIDs
python tiger/finetune_gap.py dataset.name='vk-lsvd' finetune.rqvae.train_parts='[0,9]' finetune.matching_method='none' finetune.gap_parts='[8,9]' finetune.test_parts='[9,10]'
```

**FT-ours (refresh + align + warm-start):**

1) retrain tokenizer on [0,9)
2) align refreshed SIDs into the *old* token space (Greedy or Hungarian)
3) fine-tune retriever with aligned SIDs

```bash
# retrain sasrec for embeddings on [0,9)
python sasrec/train.py dataset.name='vk-lsvd' training.save_embeddings=true dataset.train_parts='[0,9]'

# 1) retrain tokenizer on [0,9)
python rqvae-letter/train.py dataset.name='vk-lsvd' dataset.train_parts='[0,9]'

# 2) align SIDs (creates a remapped mapping file)
cd ../notebooks
jupyter notebook ChangeSemantics.ipynb
# Inside the notebook:
#   MATCHING_METHOD = "hungarian"  (or "greedy")

# 3) fine-tune TIGER on gap with aligned mapping
cd ../scripts
python tiger/finetune_gap.py dataset.name='vk-lsvd' finetune.matching_method='hungarian' finetune.gap_parts='[8,9]' finetune.test_parts='[9,10]'
```

**Full (retrain from scratch on [0,9))**:

```bash
# retrain tokenizer and retriever from scratch on [0,9)
python rqvae-letter/train.py dataset.name='vk-lsvd' dataset.train_parts='[0,9]' dataset.tiger_train_parts='[0,9]'
python tiger/train.py dataset.name='vk-lsvd' dataset.rqvae.train_parts='[0,9]' dataset.tiger.train_parts='[0,9]' dataset.tiger.test_parts='[9,10]'
```

> Note: The exact config key names (`dataset.name`, `finetune.*`) depend on the Hydra configs in this repo. If your
> config uses different names, keep the same logic but adjust the keys accordingly.

## Evaluation

### Running inference

To evaluate a trained TIGER model on the test set (typically part 9), use the inference script:

```bash
cd scripts
python tiger/inference.py dataset.name=vk-lsvd inference.use_finetune_model='true' inference.test_parts='[9,10]'
```

**What this command does:**

- Loads the trained TIGER model from the checkpoint directory
- Runs inference on the test set (specified by `inference.test_parts`)
- Computes ranking metrics (NDCG@K, Recall@K) for each batch
- Prints aggregate results to stdout

## Troubleshooting

- **OOM during decoding / evaluation**: reduce `model.num_beams` or batch size.
- **Slow runs on CPU**: use a CUDA-enabled PyTorch build and a GPU.
- **Hydra override errors**: run with `--cfg job` (Hydra) or inspect default configs under each `scripts/*/` folder to find the exact key names.
- **Dataset not found**: make sure you ran the dataset notebook and the expected `data/<dataset>/` files exist.
